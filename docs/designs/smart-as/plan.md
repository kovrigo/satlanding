## Файл для согласования

Один файл, без сервера. Три страницы сайта лежат в нём как данные: заголовок, стили, разметка, скрипт.

```
открыли файл ──► адрес после # ──► какая страница?
                   #/test/      → тест
                   #/results/   → результат
                   иначе        → лендинг (#practice, #faq — якоря лендинга)
              ──► вставить стили и разметку страницы, запустить её скрипт
переход на другую страницу (#/test/, #/results/, #/) ──► перезагрузка файла ──► снова выбор страницы
```

- Скрипты каждой страницы собираются Bun в один модуль. Импорты разрешаются из `site/js/`.
- Ссылки и переходы `/`, `/test/`, `/results/` в разметке и скриптах заменяются на `#/`, `#/test/`, `#/results/`.
- Картинки вставляются в файл как data URI.
- Шрифты грузятся с Google Fonts, как на сайте. Без интернета страница откроется системными шрифтами.
- Скрипт виджета ошибок в файл не попадает: он нужен только на тестовом сайте.
- Ответы теста хранятся в браузере, как на сайте. Переход с теста на результат сохраняет их: это тот же файл.
- Запуск: `bun scripts/export-html.ts <путь к файлу>`. Файл не коммитится: его пересобирают из `site/`.

## Что может сломаться

- В файле не сохраняются ответы, если браузер запрещает хранилище для файлов с диска. Скрипт теста тогда держит ответы в `window.name`, это переживает перезагрузку. Проверяется в Chromium.
- Переход по якорю лендинга перезагружает файл. Защита: перезагрузка только при смене страницы, проверка в списке выше.
- Новая ссылка на `/test/` в скриптах не заменится, если записана иначе. Скрипт сборки падает, если после замены в коде остались строки `"/test/"` или `"/results/"`.
